1. Konsep Dasar

  • Penjadwalan CPU = memilih proses di ready queue untuk dijalankan CPU
  • Tujuan: CPU tidak nganggur, proses cepat selesai, semua kebagian giliran
  • Ready queue = antrean | Scheduler = memilih | Dispatcher = memberi CPU (context switch)
  • Non-preemptive: proses pegang CPU sampai selesai / tunggu I/O (FCFS, SJF)
  • Preemptive: CPU bisa direbut paksa (SRTF, RR, Priority pre)

2. Process vs Thread

  • Process: program yang dieksekusi, punya address space + PCB
  • Thread: unit eksekusi dalam proses. Berbagi code/data/file, punya stack/register/PC sendiri (TCB)
  • Status: New, Ready, Running, Waiting, Terminated

3. Kriteria

  • MAKSIMALKAN: CPU Utilization (% CPU sibuk), Throughput (proses selesai / waktu)
  • MINIMALKAN: Turnaround Time, Waiting Time (total di ready queue), Response Time (sampai respons pertama)

5. Algoritma + Cara Ngerjain

FCFS (non-pre, FIFO): urut AT, jalankan sampai habis. Paling sederhana.
Kelemahan: convoy effect (proses pendek nunggu proses panjang).
SJF (non-pre): tiap CPU kosong, pilih BT terkecil dari yang SUDAH TIBA. BT sama → tiba duluan.
AWT paling kecil. Kelemahan: starvation, burst sulit diprediksi.
Prediksi: τ(n+1) = α·t(n) + (1−α)·τ(n), 0 ≤ α ≤ 1
SRTF (SJF preemptive): cek setiap ada proses tiba. BT baru < sisa proses jalan → sela.
Sisa = BT − yang sudah jalan
Priority (pre / non-pre): CPU ke prioritas tertinggi. Contoh PPT: angka kecil = tinggi (CEK SOAL!).
Kelemahan: starvation → solusi aging (prioritas naik selama menunggu).
Prio efektif = prio awal + (waktu tunggu / interval aging)
SJF = kasus khusus Priority (prioritas = 1/burst).
Round Robin (pre, time-sharing): jalan maks q, lalu ke belakang antrean. Sisa < q → jalan sesuai sisa.
PENTING: proses baru tiba masuk antrean SEBELUM proses yang baru kena potong.
q besar ≈ FCFS | q kecil = overhead context switch tinggi
Giliran = ⌈BT/q⌉   RT maks = (n−1)×q
MLQ: antrean dibagi per jenis (foreground RR, background FCFS). Antar antrean: prioritas tetap / time slice (80/20). Proses TIDAK pindah.
MLFQ: proses BOLEH pindah. Pakai CPU lama → turun. Nunggu lama → naik (aging). Contoh: Q0 RR q=8, Q1 RR q=16, Q2 FCFS.

6. Windows

  • Priority-based + preemptive, yang dijadwalkan = thread. Prioritas sama → RR
  • 32 level: 0 sistem | 1-15 variable | 16-31 real-time
  • Prioritas thread = priority class proses + prioritas relatif thread
  • Priority boost: habis I/O, thread foreground, thread kelaparan. Tidak untuk real-time

8. Langkah Ngerjain Soal

  1. Tulis tabel P, AT, BT (+ prioritas)
  2. Gambar Gantt chart, tulis angka waktu di tiap batas
  3. Baca CT dari Gantt (waktu terakhir proses selesai)
  4. Hitung TAT, WT (RT kalau diminta), lalu rata-rata
  5. Cek: WT tidak boleh negatif. CPU kosong → tulis idle
